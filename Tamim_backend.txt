4️⃣ PRECEDENCE 4: CUSTOMER CART & CHECKOUT FLOW (PHASE 1 & 2) — FOR TAMIM
================================================================================
*Enables the customer commerce lifecycle and writes actual orders into the database.

Task 4.1: Cart Management Endpoints
  - Files: `Backend/routes/cart.py`, `Backend/queries/cart.sql`
  - Endpoints to implement:
    1. `GET /cart`
       - Protected (`@require_roles('user')`). Returns active cart items from `cart` & `cart_item`.
    2. `POST /cart/items`
       - Protected (`@require_roles('user')`). Adds or updates quantity in `cart_item`.
    3. `DELETE /cart/items/<food_id>`
       - Protected (`@require_roles('user')`). Removes an item from active cart.

Task 4.2: Order Placement & Single Order Details (with Ownership Check)
  - Files: `Backend/routes/orders.py`, `Backend/queries/orders.sql`
  - Endpoints to implement:
    1. `POST /orders/checkout`
       - Protected (`@require_roles('user')`). Converts active cart into `orders` record,
         inserts pending record in `payment`, sets cart status to 'ordered'.
    2. `GET /orders/<order_id>`
       - Protected (`@require_roles(['user', 'rider', 'owner', 'admin'])`).
       - Object Ownership Check (Anti-IDOR):
         Verify in SQL: `WHERE order_id = %s AND (username = current_user OR rider_username = current_user)`
         Return 403 Forbidden or 404 Not Found if the order does not belong to the caller.
    3. `POST /orders/<order_id>/cancel`
       - Protected (`@require_roles('user')`). Cancels order if status is still 'pending'.
